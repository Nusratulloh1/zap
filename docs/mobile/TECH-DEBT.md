# Технический долг мобильного приложения

Список сознательно отложенного. Ничего из этого не блокирует разработку,
но **всё должно быть закрыто до публикации в сторах**.

## Блокеры релиза

### 1. `release` помечен как debuggableVariant

`apps/mobile/android/app/build.gradle`:

```gradle
react {
    debuggableVariants = ["debug", "release"]
}
```

Так сделано потому, что Metro внутри Gradle на машине сборки падает по памяти
(V8 «Last few GCs», следом умирает демон Gradle). Из-за флага RN-плагин не
собирает JS сам, и бандл кладётся заранее командой из `RUN.md`.

**Побочный эффект:** релизный APK помечен `debuggable` — в стор такой нельзя.

**Как чинить:** собрать на машине с большей памятью (или в CI), вернув
`debuggableVariants = ["debug"]`. Страховка в том же `build.gradle`
(проверка на `mergeReleaseAssets`) тогда станет не нужна, но мешать не будет.

### 2. Звуки только на Android

`react-native-sound` берёт файлы:

* Android — `android/app/src/main/res/raw/*.mp3` — **сделано**;
* iOS — из бандла приложения, файлы нужно добавить в Xcode-проект.

Ассеты лежат в `apps/mobile/assets/sounds/`. Нужно добавить их в target
приложения в Xcode (Build Phases → Copy Bundle Resources). Делать на macOS.

### 3. Шесть звуков — синтезированные заглушки

Реальный ассет один: `split.mp3` (разрыв бумаги из `docs/product`).
Остальные сгенерированы скриптом `scratchpad/mksounds.py` и
`mksplitdone.py`: `scan`, `paid`, `share`, `reminder`, `everyone_paid`,
`split_done`.

Звучат прилично и попадают в моменты продукта, но это не дизайнерские звуки.
**Замена тривиальна:** положить файлы с теми же именами в
`android/app/src/main/res/raw/` — код не меняется.

## Внешнее (не в нашем коде)

### 4. SMS не доставляются

Аккаунт `eduplus` на `send.smsxabar.uz` 27.08.2026 отдавал
`error-code 102: "Account lock"`. Сейчас API принимает (`200 Request is
received`), но сообщения до телефона не доходят.

Проверить у провайдера: баланс, статус аккаунта, регистрацию originator
`3700` для Ucell.

**Наш код при этом врёт в журнале:** `SmsLog.status` ставится `sent` по
HTTP 2xx, хотя провайдер сказал лишь «принял». Стоит переименовать в
`accepted` и принимать DLR-callback, иначе инцидент снова будет незаметен
несколько дней.

## Известные ограничения

* Share Card (vision B§7) — сделан. `react-native-view-shot` установлен и
  собирается; снимок карточки уходит в системный шеринг. Если библиотека
  почему-то не подхватится, `lib/shareCard.ts` молча отправит ссылку вместо
  картинки — продукт не ломается.
* Боковой отступ экранов сведён к `SCREEN_PAD_X = 16`. Веб при этом держит
  внутренние страницы на `px-6` (24) — паритет с вебом здесь сознательно
  нарушен по решению продукта.
