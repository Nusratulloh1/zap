# ZAP! — локальная разработка и тестирование

Весь продукт (PWA + NestJS + PostgreSQL + Socket.IO + SMS dry-run) поднимается
одной командой и полностью изолирован от продакшена.

## Требования

- Node.js ≥ 20, pnpm ≥ 9 (`corepack enable`)
- Docker Desktop — **опционально**: без него `dev:all` сам поднимает настоящий
  embedded-PostgreSQL (каталог `backend/.pgdata`, порт тот же)

## Одна команда

```bash
pnpm install && (cd backend && pnpm install)   # один раз после клона
pnpm dev:all
```

Что происходит:
1. **БД**: Docker есть → `docker compose -f backend/docker-compose.dev.yml up -d`
   (Postgres :5433, volume `zap_pg_dev`, Adminer http://localhost:8081, логин
   `zap`/`zap`, сервер `db`). Docker нет → embedded-PostgreSQL на :5433.
2. **Миграции** применяются автоматически (`prisma migrate dev`).
3. **Бэкенд**: Nest watch-mode на **:3202**, окружение `backend/.env.development`
   (создаётся из `.env.development.example` при первом запуске; SMS dry-run,
   dev-JWT, CORS на localhost).
4. **Фронт**: Vite на **:5173** с `VITE_API_URL=http://localhost:3202`.

`Ctrl+C` останавливает всё; `pnpm dev:stop` — принудительный teardown
(compose down + освобождение портов 5173/3202/5433).

Обычный мок-режим (без бэкенда) остаётся как был: `pnpm dev`.

## SMS dry-run — как логиниться локально

Реальные SMS-креды **не нужны и нигде не лежат**. Каждая «отправка»:
- печатается в консоли бэкенда заметным блоком `┏━━ SMS DRY-RUN ━━ [SMS→9989…] ZAP! Код: 123456`;
- пишется в таблицу `SmsLog` со статусом `dry_run`;
- доступна на dev-ручке `GET /dev/sms/latest?phone=9989…` (отключена при
  `NODE_ENV=production`).

На экране «Код из SMS» в dev-режиме есть кнопка **«DEV · получить код»** — тянет
код с этой ручки и автозаполняет поле: полный логин в три тапа. Из
продакшен-сборки кнопка вырезается три-шейкингом (`import.meta.env.DEV`).

## Двухпользовательский флоу (организатор + участник)

1. Обычное окно: логин 998900000001 → скан → «Демо-чек» → «Разделить» →
   «+ Номер» → 90 000 00 02 → «Сплит · оплатить» → PIN 1111 → экран «Покажите QR».
2. **Инкогнито-окно**: откройте `http://localhost:5173/s/{код}` (код виден на
   share-экране). Введите номер 998900000002 → видна ваша доля → «Внести» —
   код OTP в dev-режиме подставляется автоматически.
3. У организатора события летят живьём через локальный Socket.IO: «открыл
   ссылку», «оплатил», автозакрытие и кэшбэк ×2 — без перезагрузки.

## Камера и PWA локально

- На `http://localhost` камера и вся PWA-механика (SW, манифест) работают без
  HTTPS — это доверенный origin в Chrome/Safari. Проверено.
- **Тест с телефона по Wi-Fi** (реальная камера/установка): `pnpm dev:https`
  (нужен запущенный `pnpm dev:all` в соседнем терминале — он держит API):
  1. скрипт печатает адрес вида `https://192.168.x.x:5173`;
  2. телефон в той же сети → открыть адрес → доверить mkcert-сертификат;
  3. установить PWA, сканировать реальный QR с адресом
     `http://<ip-пк>:5173/s/{код}`.
  API проксируется через тот же https-origin (`/api`) — mixed-content нет;
  CORS в dev принимает LAN-адреса (192.168.*/10.*).

## Троблшутинг

- **Порт занят** (`5173/3202/5433`): `pnpm dev:stop`, затем снова `pnpm dev:all`.
- **Docker не запущен**: не проблема — автоматически включается embedded-PG.
  Хотите Docker-путь — запустите Docker Desktop и перезапустите `dev:all`.
- **Prisma drift / сломанная схема**: `pnpm db:reset` (локальная БД пересоздаётся).
- **`migrate dev` просит shadow db**: локальный пользователь `zap` — суперюзер
  в обоих вариантах БД, работает из коробки.
- **API упал при старте**: смотрите префикс `[api]` в общем логе — оркестратор
  останавливает весь стек при падении любого процесса.

## Проверка (что гоняется в CI/локально)

- `cd backend && pnpm test:e2e` — приёмочный бэкенд-гейт на настоящем PostgreSQL.
- `FRONT_URL=http://localhost:5173 API_URL=http://localhost:3202 node scripts/real-smoke.mjs`
  — UI-golden-path против локального бэкенда: организатор (полный флоу) +
  участник из второго контекста + realtime-автозакрытие + кэшбэк в БД;
  коды берутся с `/dev/sms/latest`.
